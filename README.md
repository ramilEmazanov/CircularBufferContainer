# CircularBufferContainer — кольцевой буфер на C++

Шаблонный контейнер с интерфейсом в стиле STL, собственными итераторами и поддержкой пользовательского аллокатора. Реализован в двух режимах: буфер фиксированной ёмкости с перезаписью элементов и расширяемый буфер, увеличивающий ёмкость при заполнении.

Проект выполнен в рамках лабораторной работы № 6 в ИТМО. Главный акцент — устройство контейнеров C++: управление сырой памятью, жизненным циклом объектов и логическим порядком элементов в кольцевом хранилище. Для хранения данных внутри контейнера не используются готовые стандартные контейнеры и адаптеры.

**Стек:** C++23 · STL-алгоритмы · шаблоны · allocator_traits · CMake · GoogleTest · CTest

## Возможности

- **Два режима работы:** фиксированная и автоматически расширяемая ёмкость, выбираемые параметром шаблона `Extendable`.
- **Операции с обоих концов:** `push_back`, `push_front`, `pop_back`, `pop_front`, `front` и `back`.
- **Модификация содержимого:** вставка значения, нескольких копий, диапазона или списка инициализации; удаление элемента и диапазона; `assign` и `clear`.
- **Управление ёмкостью:** получение `capacity`, проверка заполнения и перераспределение памяти через `resize`.
- **Итераторы произвольного доступа:** арифметика, сравнение, индексирование и вычисление расстояния с учётом кольцевой структуры.
- **Константный и обратный обход:** `const_iterator`, `reverse_iterator`, `const_reverse_iterator`, методы `cbegin`, `cend`, `rbegin` и `rend`.
- **Интеграция с алгоритмами:** в тестах проверяется работа `std::sort`, `std::reverse` и `std::distance`.
- **Конструирование и копирование:** создание по ёмкости, количеству и значению, диапазону и списку инициализации; копирующий конструктор и присваивание.
- **Настраиваемое выделение памяти:** параметр `Allocator` и доступ к нему через `get_allocator`.

## Как устроен контейнер

### Кольцевое хранение

Элементы размещаются в выделенном блоке памяти. Контейнер хранит границы блока, указатель на первый логический элемент, позицию следующей вставки в конец и число элементов.

При достижении физического конца блока указатель возвращается к его началу. Поэтому логическая последовательность может пересекать границу выделенной памяти:

```text
Физические позиции:  0   1   2   3   4
Содержимое:         [8] [9] [ ] [6] [7]
                                ↑
                         логическое начало

Порядок обхода: 6 → 7 → 8 → 9
```

Переходы через границу и преобразование указателей в логические индексы вынесены во вспомогательные методы. Итераторы представляют элементы в логическом порядке независимо от их физического расположения.

### Фиксированная и расширяемая ёмкость

```cpp
circular_buffer<int> fixed(3);
circular_buffer<int, true> growing(3);
```

В фиксированном режиме `push_back` в заполненный буфер перезаписывает первый логический элемент, а `push_front` — последний. Ёмкость и размер заполненного контейнера сохраняются.

В расширяемом режиме вставка в заполненный буфер приводит к выделению нового блока; текущая реализация вставок рассчитывает новую ёмкость как удвоенную предыдущую. Элементы копируются в новое хранилище, затем старая память освобождается.

Операции добавления и удаления на концах без перераспределения памяти выполняются за O(1). Расширение требует O(N) из-за копирования элементов. Вставка в середину и удаление диапазона также связаны с переносом элементов.

### Память и аллокатор

Выделение памяти отделено от конструирования объектов: контейнер использует `allocate`, `construct`, `destroy` и `deallocate` через `std::allocator_traits`. Это позволяет резервировать хранилище без предварительного создания всех элементов и работать с пользовательским аллокатором.

В тестах используются объекты со счётчиками вызовов конструкторов и деструкторов, а также аллокатор со счётчиками выделений. Отдельно проверяется возможность создать контейнер для типа без конструктора по умолчанию.

### Итераторы

`base_iterator<IsConst>` объединяет реализацию обычного и константного обхода. Итератор хранит ссылку на контейнер в виде указателя и позицию элемента, а арифметика учитывает логический индекс в кольце.

`base_reverse_iterator<IsConst>` строит обратный обход поверх базового итератора. Реализованы разыменование, сдвиги, индексирование, сравнения, вычисление расстояния и получение базового итератора через `base()`.

## Пример использования

```cpp
#include <algorithm>
#include <iostream>

#include "circular_buffer.h"

int main() {
    circular_buffer<int> history(3);
    history.push_back(1);
    history.push_back(2);
    history.push_back(3);
    history.push_back(4);  // Логический порядок: 2, 3, 4.

    for (int value : history) {
        std::cout << value << ' ';
    }
    std::cout << '\n';

    circular_buffer<int, true> values(2);
    values.push_back(3);
    values.push_back(1);
    values.push_back(2);  // Ёмкость увеличивается с 2 до 4.

    std::sort(values.begin(), values.end());
    for (auto it = values.rbegin(); it != values.rend(); ++it) {
        std::cout << *it << ' ';
    }
    std::cout << '\n';
}
```

Ожидаемый вывод:

```text
2 3 4
3 2 1
```

Реализация находится в одном заголовочном файле [lib/circular_buffer.h](lib/circular_buffer.h). Чтобы собрать пример, сохраните его как `example.cpp` в корне проекта:

```bash
c++ -std=c++23 -Ilib example.cpp -o example
./example
```

## Сборка и тестирование

Понадобятся Git, CMake и компилятор с поддержкой C++23. При первоначальной конфигурации FetchContent загружает GoogleTest, если подходящий пакет не найден локально. Команды ниже выполняются из корня проекта:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DRUN_EXT_TESTS=ON
cmake --build build
ctest --test-dir build --output-on-failure
```

`RUN_EXT_TESTS` включает дополнительные проверки расширяемого режима в типизированных тестах. В текущей конфигурации опция включена по умолчанию; файл `ext_buffer_ut.cpp` также входит в основной список исходников тестовой цели.

Тесты охватывают следующие группы сценариев:

| Группа | Что проверяется |
| --- | --- |
| Базовые операции | Добавление и удаление с обоих концов, заполнение и переход через границу буфера |
| Конструкторы и присваивание | Копирование, пустые и заполненные буферы, диапазоны и списки инициализации |
| Модификация | Вставки, возвращаемые итераторы, удаление диапазонов и изменение ёмкости |
| Прямые итераторы | Арифметика, сравнения, расстояния и использование стандартных алгоритмов |
| Обратные итераторы | Обратный обход, разыменование, сдвиги, индексирование и граничные позиции |
| Аллокаторы и типы элементов | Выделение памяти, вызовы конструкторов и поддержка типа без конструктора по умолчанию |
| Требования к интерфейсу | Проверки через concepts для Container, SequenceContainer, ReversibleContainer и AllocatorAwareContainer |

Часть тестов предоставлена в задании; реализация дополнена проверками конструкторов, присваивания, вставок, прямых и обратных итераторов.

Для сбора покрытия предусмотрена конфигурация с `gcovr` и компилятором GCC/Clang:

```bash
cmake -S . -B build-coverage -DCMAKE_BUILD_TYPE=Debug -DWITH_COVERAGE=ON
cmake --build build-coverage
cmake --build build-coverage --target coverage
```

HTML-отчёт формируется в `build-coverage/coverage.html`.

- Разработку обобщённого контейнера с интерфейсом в стиле STL.
